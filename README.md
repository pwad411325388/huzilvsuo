# 沪紫律所股票索赔小程序一期

V0.13 本地验收版。原生微信小程序提供股民、券商及销售三端。PC 浏览器提供运营后台。共用本地业务接口和 SQLite 数据。

## 启动

需要 Node.js 24 或更高版本。首次启动前安装锁定的依赖。

```powershell
$env:LOCAL_TEST_ACCOUNTS = '1'
npm ci
npm start
```

上面的开关仅供本地验收。首次启动会为测试库创建后台验收账号 `local-admin`，密码为 `LocalAdmin!012`。它仅在尚无管理员时生效。已有管理员以原凭据登录。开启测试模式时可使用虚构券商和案件样例。默认服务只监听 `127.0.0.1:7101`。

需要用自定的首个后台账号时，在首次启动前设定 `APP_ADMIN_ACCOUNT`、`APP_ADMIN_PASSWORD`，可选 `APP_ADMIN_NAME`。关闭 `LOCAL_TEST_ACCOUNTS` 后，新数据库不会生成虚构账号或业务样例。

SQLite 默认使用 `.runtime/demo.sqlite`。用 `DEMO_DB` 指定隔离的测试库或 `:memory:`。`DEMO_CASE_CUTOFF` 可设为 `YYYY-MM-DD`，创建数据库时写入，默认取上海时区当月首日。正式案件分界日由业务确认。切换浏览器测试端口时，可用 `DEMO_PORT`，原生小程序调试端口在 `miniprogram/client.js`。

## 在微信开发者工具验收

用微信开发者工具导入项目目录，`project.config.json` 已指定 `miniprogram/` 作为小程序目录。点击「编译」，普通编译默认显示登录页。调试服务使用本机 HTTP。真实微信扫码、真机和正式域名待联调。

1. **股民自助注册。** 登录页点「首次使用？注册股民账号」。填未使用的虚构手机号和自设密码（至少 8 位）。登录后打开「我的」，顶部显示手机号作为初始名称及登录账号。修改显示名称后退出，仍用原手机号和原密码登录。留资姓名和联系电话在独立的留资业务区展示。
2. **后台开通销售账号。** 用后台账号登录 [PC 后台](http://127.0.0.1:7101/admin)，进入「账号管理 → 销售账号开通」。新业务选择「新增销售」，为有历史券商绑定的销售开户时，选择对应旧销售记录。填写销售姓名和专用账号后提交。新销售和券商的默认初始密码统一为 `12345678`。首次登录小程序时，用初始密码设置个人密码，再用新密码登录。销售端首页登记券商合作，「我的」显示登记姓名和登录账号。
3. **后台开通券商账号。** 销售登记合作后，登录 PC 后台，在「账号管理 → 券商合作与开户」按券商名称、账号或合作负责人搜索，也可筛选待开户、已开户或已注销。待开户排在最前，每页 20 家。点击「展开开户」，填写专用账号并点击「开通账号」。已开户记录默认收起，点击「查看资料」展开。开户后保留当前搜索条件。券商按上一步的首次登录流程设置个人密码，在首页看推广与统计，在「我的」看名称、账号及台账。
4. **调试扫码归属。** 退出登录，在微信开发者工具的编译模式中选择「券商 A 测试扫码」或用开户后取得的推广码创建场景，页面设为 `pages/home/index`，参数为 `scene=推广码`。未登录时先从 A 场景编译，再从 B 场景编译，从同一个注册入口完成注册。后台查看首次来源和当前券商均为 A；券商台账与合作统计按当前渠道归属读取，该客户之后提交的留资自动交给券商 A 绑定的销售。授权改归后重复扫码也保持改归结果。浏览器可用 [券商 A 链接](http://127.0.0.1:7101/?promo=DEMO-A) 和 [券商 B 链接](http://127.0.0.1:7101/?promo=DEMO-B) 在同一浏览器会话验证。直接注册的账号初始无归属，首次有效扫码可补绑。
5. **业务联动。** 股民留资后在「我的」查看记录。后台录入客户签约结果、创建新案件并更新状态。销售和券商可切换看板指标，后台可筛选并导出 Excel。查询和导出使用同一套业务编号、销售姓名和日期字段。

退出登录在三个小程序端的「我的」顶部。当前会话会被服务端撤销。保留的有效会话可以在下次打开时恢复，默认有效期七天。

同一浏览器可同时打开 [PC 后台](http://127.0.0.1:7101/admin) 和多个 [业务端](http://127.0.0.1:7101/) 新标签页。每个业务标签页可分别登录股民、销售或券商账号，刷新沿用各自登录态。升级前从首页进入后台的旧登录态需在新后台入口重新登录一次。

## 券商推荐、公司派单与销售跟进

- **已确认业务规则：** 券商推荐客户提交留资时，当前券商绑定的销售直接成为该条留资的经办人。股票未配置或公司负责人不同，仍按券商派单。券商缺少可用销售时进入待分配。自然流入的留资按股票公司负责人派单。同一股民不同股票留资可以分派给不同销售，跟进记录和权限按留资隔离。
- **配置入口：** 后台「公司与派单 → 新增公司派单配置」填写公司名称、股票代码、股票别名及负责销售。负责销售必须已开户且账号正常。对于自然流入的留资，名称/别名与代码精确匹配同一公司才按公司派单；冲突、无法匹配、配置停用或销售不可用时进入「新留资待分配」。别名与代码不可占用另一公司的配置。新增配置不会回填旧留资，修改负责人只作用于之后提交的新留资。
- **人工处理：** 后台「公司与派单」筛选新留资待分配、历史待核对、已分配或全部，点击「核对并分配 / 核对与转派」。选择经办销售并填写说明。自然流入留资还需核对公司，券商推荐留资的公司资料可选填。原始股票输入保留。转派后旧销售不能再提交跟进，新销售可看同条留资此前的跟进；每次分派后重新进入当前经办人的待跟进列表。多管理员同时修改会检测版本冲突。
- **使用端：** 销售网页/小程序首页「分派给我的留资」切换待跟进、已跟进、全部，看到对应联系方式、股票、来源渠道和该条留资的案件，按条保存跟进。「我的」提供销售数据统计，包含已关联的律所历史登记。历史客户级跟进仅在后台供核对，不擅自归入任一股票留资。
- **本地实现默认，非正式业务定稿：** 升级时按当前券商绑定的可用销售补派尚无经办人的推荐留资。既有经办人及跟进记录继续保留。股票代码输入扩到 20 字，支持本地配置字母、数字、点、短横线，并统一大小写及全半角匹配；没有接行情库，也不代表已确认支持任何具体市场。正式支持市场及签约业绩归属仍待业务确认。

验收可配置「虚构公司甲 / TSTA → 销售 B」和「虚构公司乙 / 000002 → 销售 A」。让券商 A 绑定销售 A。提交公司甲时，自然注册客户的留资归销售 B，券商 A 推荐客户的留资归销售 A。同一自然流入客户再提交公司乙，只该条归销售 A。股票无法匹配时，自然流入的留资进入待分配，券商推荐的留资仍交给销售 A。调整客户券商或券商合作负责人不应改变这些留资经办人。更改公司配置不能自动挪动已分派留资。

## 后台数据模块

采用深蓝品牌栏、左侧功能导航、统计卡片与明细表格，数据来自当前数据库；未复制或导入原型真实客户数据。返佣、金额、奖励控件及相关指标不展示，原存储字段保留。

- **数据总览：** 留资条数、去重留资客户人数、合作渠道数、待分配留资、在办案件、已结案件、本月新增留资和本月签约客户。8 张卡片均可点击进入独立明细界面（0 条也可进入），按与卡片一致的统计范围展示记录，支持关键词搜索、每页 20 条和返回总览。客户明细一人一行，汇总股票线索、电话、首次/当前券商、客户归属销售、各条留资的经办销售及签约日期；案件展示可读编号和案件名称。总计与检索结果分别显示。也可快捷进入新待分配或历史待核对。
- **销售看板：** 分列券商合作统计（渠道数、渠道留资客户）与经办留资统计（留资数、客户数、待跟进/已跟进、对应在办/已结案件）。本地口径按当前分派计算，客户在每位销售内去重，跨销售人数不可直接相加。未把经办人数或案件数定义为正式业绩归属。
- **渠道管理：** 渠道合作负责人、账号状态、合作日期及客户/留资/案件计数；自然流入单列但不创建券商记录。可调整合作负责人、查看该渠道案件或跳转账号维护。
- **客户案件：** 客户、股票、来源渠道、经办销售和状态筛选。案件按件列示，持久化可读编号 `AJ-000001`；展示对应留资的经办人，保留录入和状态更新。统计只含当前分界日及之后案件；在办为已受理或诉讼中，待受理单列状态。
- **数据报表：** 留资、签约、案件、销售汇总、渠道汇总五类，查询和 Excel/兼容 CSV 导出共用筛选与字段计算。留资/案件的销售取经办人；签约仍按客户记录，每人一条，销售指渠道合作负责人，并明确提示该口径待确认。日期为实际日期，数值统计为数值单元格，无财务列。

### 律所登记台账

在 PC 后台打开「律所登记台账」可分页检索工作簿中的登记记录。每行对应原表的一条登记，相同股民可能涉及多只股票或多次登记。台账保留原表行号、登记销售、股票及可识别的进度，材料登记时间和立案时间分别展示。历史登记与小程序留资分别存储，在销售「我的」统计中按账号关联一并展示，不会生成新的派单或伪造签约记录。

管理员可在台账中打开「按销售姓名批量开户」。预览会列出每位销售、原表标记、登记条数和处理方式。新开户的销售使用统一默认初始密码 `12345678`，可点击「保存新账号清单」交付。姓名前的单个业务星号与同名销售合并，职务、同名冲突及有争议的归属留待管理员核对。重复执行批量开户会沿用已开户销售的现有密码。销售首次登录时设置个人密码并重新登录，首页「我的登记客户」展示所关联的股民和股票，可点「查看全部登记记录」检索明细。

在台账行点击「关联账号」也可以单独关联销售或股民账号，核对身份、来源及影响条数后确认。股民关联同时符合登记姓名和单一有效合同手机号的记录，用已注册的股民账号进入小程序「我的 → 律所登记记录」即可查看。管理员可在同一处解除关联。

本地数据源默认为项目上级目录的 `测试数据/诉讼组—股民登记表格.xlsx`。在 WPS 或 Excel 保存修改后，后台点击「从本地表格更新」。系统读取「股民登记总表」并在校验完成后更新本地快照。更新时需要 Python 3，使用标准库。部署到其他目录时可通过 `REGISTRY_WORKBOOK` 指定工作簿绝对路径，`REGISTRY_PYTHON` 可指定 Python 可执行文件。更新方向为工作簿到应用，账号关联在后台维护。

### 销售累计与期间统计

销售登录网页或小程序后，打开「我的 → 我的数据」。默认「全部」统计截至今天的累计记录，包含当前负责的渠道客户、经办留资和已经关联到该销售账号的律所登记。点「本月」使用上海时区当月首日至今天，也可选起止日期后点「按日期查看」。卡片与明细使用相同范围，明细每页 20 条。

- **来源渠道：** 合并当前负责的券商及历史登记中已识别的来源名称。历史来源名称只用于统计，不会自动开通券商账号或建立归属。
- **客户档案：** 先按明确关联的股民身份合并，再按完整姓名和有效手机号核对。缺少手机号、未关联身份的历史记录保留独立档案，单位为「份」，不将其视为已经确认的独立客户人数。
- **已签约客户：** 只计实际签约记录或公司同步的明确签约状态。当前原表没有签约字段，不根据立案或结案推断签约。
- **已结案：** 包含有明确结案状态的本地案件和历史登记；公司同步的最新状态优先。历史数据按结案登记记录计件。

日期筛选按客户/材料登记日期选取数据，展示这些记录当前的签约与结案情况。券商来源按合作登记日期，历史来源按材料登记日期。原表没有签约日期、结案日期，因此「本月」不是当月实际签约或结案事件统计。缺少有效日期的记录仅纳入「全部」，页面会提示。销售间仍按各自授权范围读取，解除台账关联后重新进入页面即不再计入。

**用户确认（2026-11-18）：上述登记日期口径仅用于当前测试。正式上线前必须切换为各指标的实际发生日期。** 客户登记按实际登记日期，渠道合作按实际合作日期，签约按实际签约日期，结案按实际结案日期。卡片、明细和期间汇总须使用同一业务事件日期，不能用材料登记日期或数据同步时间替代签约、结案日期。

上线前需补齐公司数据源的签约、结案事件日期及对应稳定记录标识，并验证跨月、起止日期边界和累计/明细一致性。历史记录缺少实际发生日期时保留为日期待核，不推算或补造日期，不计入无法确定归属月份的期间统计。当前实现尚未完成这项正式口径切换，不能将测试口径作为正式上线验收结果。

### 原生小程序案件进度

在微信开发者工具打开本项目并编译。股民点「我的 → 留资记录」里的股票，可进入该条留资，再选具体案件。历史登记从「我的 → 律所登记记录」点入。经办销售从首页「分派给我的留资」点留资或具体案件，历史登记从「我的登记客户 → 查看全部登记记录」点入。

详情以纵向进度条展示该记录当前阶段的节点。「当前」给出所在位置，带勾的「已完成」表示有完成证据，空心圆表示本阶段参考节点。补料和发回重审在已发生时显示。缺少具体节点的记录显示已有粗状态或待同步提示。销售可查看该记录的真实合同号，股民接口仅提供进度。立案补件与债权申报补件分别使用各自的角色文案。

2026-11-18 本地工作簿的 30,900 条登记中，4,989 条可以确认当前节点。已结案 3,320 条，一审待开庭 681 条，二审上诉待开庭 338 条，执行中 448 条，已调解待支付 202 条。一审待开庭的组合依据是明确的「已立案未开庭」、可辨认的一审案号且无退回或后续程序冲突。结案标记只确认结案本身。其余登记根据证据展示已有粗状态、待核对或未同步。

正式对接需要公司系统提供每条留资、案件或历史登记的稳定标识、阶段、当前节点、版本，以及销售有权查看的独立合同号。判决生效、补料、发回重审、债权申报结果、股民到账等节点需要公司确认阶段与状态字典。付款经手方和股民实际到账要有各自的来源字段。本地原表的合同备注、合同联系电话和案号均有各自用途，主表目前缺少独立合同号。

可在服务所在机器用 `node scripts/sync_progress.mjs <快照.json> --db <现有数据库文件>` 单向同步公司导出的 JSON 数组。`kind` 支持 `lead`、`case`、`registry`，`id` 分别取本地留资 ID、案件 ID、台账内部登记键。接正式接口时须先维护公司记录与本地记录的一一对应。每条快照提交递增整数 `revision`、成对的 `stage` 和 `node`、可选的 `contractNumber`。完整快照优先于台账，显式提交两个 `null` 清空节点，省略合同号会清空已同步的合同号。重复同版同内容可重试，版本冲突会整批回滚。阶段和节点取值见 [进度字典](./progress-dictionary.mjs)。

公司快照可通过 `completedNodes` 提供本阶段有明确完成证据的节点代码数组。例如立案阶段当前为 `supplement`，若来源确认材料已备好，可填写 `["preparing"]`。只有明确发生过的条件分支会进入进度条。新版本省略该字段或提交空数组会清空该快照的完成证据。小程序留资记录自身的创建时间可作为该条「已留资」的证据，历史登记时间不用于推算签约、判决或到账。

## 客户检索与签约

- 「客户签约」中的「调整客户归属」和「登记客户实际签约」均输入姓名检索，也可用手机号或登录账号查找。完整姓名匹配优先；同名客户展示电话、当前券商和登录账号，必须点击确认具体客户后才能保存。修改搜索内容会取消旧选择，避免误操作。
- 调整归属仅检索已有券商归属的客户；实际签约仅检索有姓名、电话和留资的客户。每批展示 20 位，可继续加载匹配结果。支持方向键选择、回车确认以及 Esc 收起结果。
- 下方「客户记录」新增「股票线索」列，可按股票名称/代码、姓名、电话、登录账号、首次或当前券商检索。每位客户只列一行，合并全部股票线索并标出重复留资条数；每页 20 位，搜索与重置不清空上方正在填写的表单。

## 账号管理与忘记密码验收

1. **查找全部账号。** PC 后台「账号管理 → 全部账号」包含股民、销售、券商和管理员。按姓名/登录账号、角色、状态筛选。待留资股民也会列出。后台顶部「账号安全」用于管理员修改自己的密码、生成个人恢复码。
2. **后台重置密码。** 找到目标账号，点击「重置密码」，输入当前管理员密码和给用户的临时密码，再确认账号与申请人身份。旧密码、全部设备会话和旧恢复码立即失效。用户用临时密码登录后，只能设置自己的新密码，完成后重新登录才能访问业务。重置当前管理员自身密码也会退出当前登录。
3. **注销和恢复。** 「注销账号」采用停用登录，保留账号标识及留资、签约、案件、渠道归属、审计记录，不执行个人资料删除。不可注销当前管理员或最后一个可用管理员。注销后所有会话与恢复码失效，券商推广码停止接纳新客户，已有客户数据和统计保留。后台可「恢复账号」，恢复后旧会话和旧恢复码仍不可用。用户名继续保留，不允许重新注册冒领历史记录。
4. **提前保存个人恢复码。** 网页/小程序登录后打开「我的 → 账号安全」，输入当前密码，生成新的恢复码并妥善保存。管理员在后台顶部「账号安全」操作。该码只显示一次，可用一次，无固定期限；重新生成、修改/重置密码、注销账号都会使旧码失效。页面关闭或退出后不再展示，服务端仅保存散列。
5. **用户自行找回。** 登录页「忘记密码」，填登录账号、已保存的恢复码、新密码和确认密码。成功后使用新密码正常登录，不自动登录。恢复码不能跨账号或重复使用；所有旧会话和恢复码失效。每个账号的恢复入口 15 分钟内最多尝试 5 次，超过需等待或由后台重新签发码；正常密码登录不会因此被锁定。
6. **未保存恢复码。** 管理员通过既有联系方式/业务材料核实账号本人后，在「全部账号 → 临时恢复码」输入管理员密码并确认核实，签发一次性临时码，30 分钟有效。将码交给本人后，由本人在「忘记密码」设置新密码。新码使此前的恢复码失效。也可采用第 2 步直接重置临时密码。系统没有自动完成线下身份核实，只有账号/手机号不构成找回凭据。

当前没有接入短信、邮件或微信身份验证，使用恢复码完成本地找回流程。恢复码设计参考 [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) 的离线恢复码、单次使用、撤销旧会话等建议。上述全部敏感账号操作记录审计，不记录密码或恢复码原文。

## 迁移与权限

- 启动时在原 SQLite 库迁移券商账号散列，并补齐既有销售业务记录。现有留资、案件、签约、券商和归属继续保留。旧临时股民身份需重新注册。注册手机号与旧留资手机号相同，也不会自动认领旧记录。
- 股民账号只可自助注册为股民。后台创建券商和销售账号。登录角色、账户标识和访问范围均取自服务端。密码按账号加盐散列，会话令牌以散列保存。浏览器使用 HttpOnly 会话 Cookie，小程序使用本地保存的会话凭证。
- 匿名推广入口由服务端验证并保存首次有效来源。浏览器用临时 Cookie 维持待关联会话，待关联记录有效期 24 小时。注册时在数据库事务里写入首次来源和当前归属。小程序本地调试沿用相同规则，正式微信侧用 OpenID 衔接仍待联调。
- 券商看板显示本渠道客户的留资姓名与后台登记的案件名称。手机号向有权销售和后台显示。当前展示与统计按当前渠道归属，正式历史归属口径待确认。
- WPS 保持在本地业务流之外，正式接入需同结构样表、编号和字段映射、测试文件授权。案件状态首期由后台维护。正式手机身份核验和账号交付流程待确认。
